Tables & table views

Audit + design · no source changes
Executive summary

The table is close to complete; the leverage is shipping the prototype and stopping the fork

UIx already contains a well-considered table system. A production-grade primitive ships today (density, sticky header, sort affordance, row pinning, selection state, frozen identifier column), and the full v2 vision is specified by demonstration in packages/tokens/tables.html. The gap is not vision — it is distance between the demonstrated spec and the shipped contract, plus a downstream adoption problem where Tensor re-implements the table locally.

Adoption exists in UIx but downstream forks it
Three headline findings. (1) Roughly ten table capabilities are fully designed in tables.html but never shipped into table.css or a React wrapper — selection column, bulk bar, row actions, expandable rows, inline edit, column resize/reorder, search+highlight, typed filters, saved views, and the responsive ladder. (2) Per your own Docs/2026-06-25-analyst-dx-token-proposal.md, Tensor forks Table in data-table.tsx instead of consuming UIx — so shipped investment goes unused. (3) The width problem in part 3 is real and only half-solved: the shell collapses the sidebar to a 56px rail, but there is no fully-hidden nav, no full-bleed table, and no table-scoped focus mode.
Method

How to read this

Every claim below is grounded in the source: packages/tokens/styles/components/*.css, packages/react/src/components/*.tsx, the two showcases (index.html, tables.html) and their JS harness (guide/app.js), and the design docs. Tensor itself is a sibling repo and is not present in this workspace — statements about Tensor are sourced from the UIx docs, not from reading Tensor code.

The audit separates three questions that are easy to conflate: does the pattern exist as a shipped primitive (a class in table.css and/or a prop in Table.tsx), does it exist only as a styleguide prototype (rendered by demo JS, not distributed), and does it exist but go unconsumed. Those lead to different fixes: ship it, productize it, or enforce adoption.

Part 3 · Recommended outcome

A three-tier nav ladder + a table-scoped focus mode

The cleanest answer is progressive reveal, not one big toggle. Give the operator three resting nav widths and one immersive escape hatch, all persisted, all keyboard-reachable. This directly satisfies “collapse the sidebar and expand the table” while keeping the everyday layout intact.

The recommendation, in four parts
  1. Promote the binary collapse to a three-state nav. Replace the boolean data-collapsed with data-nav="full | rail | hidden". Full (248) and rail (56) already exist; add hidden (0) for the many-column case where even the rail is in the way.
  2. Add a table-scoped Focus mode. A maximize control in the table toolbar sets data-focus on the shell, hiding the sidebar and the topbar so the grid uses the full viewport. Esc exits and restores the previous nav state and focus. This is the “immersion across many columns” row already named in the tables.html detail ladder.
  3. Make the table full-bleed on demand. The shell’s main region has a --uix-space-7 (32px) gutter on all sides. For a wide grid, opt into .uix-shell__main--bleed so the table runs edge-to-edge and reclaims 64px. Pair with the shipped frozen identifier column so the leftmost column stays legible during horizontal scroll.
  4. Persist and shortcut it. Store the nav state per user (and optionally per surface) with the same readViewPrefs / writeViewPrefs localStorage pattern the table view menu already uses. Bind [ to cycle nav width and give Focus mode a shortcut; manage focus and aria-expanded on toggle.
Design sketch — CSS (design only; not applied to source)
/* app-shell.css — today */
.uix-shell { grid-template-columns: var(--uix-sidebar-w) 1fr; transition: grid-template-columns var(--uix-dur) var(--uix-ease-out); }
.uix-shell[data-collapsed] { grid-template-columns: 56px 1fr; }

/* proposed — one attribute, three tiers + focus + bleed */
.uix-shell[data-nav="full"]   { grid-template-columns: var(--uix-sidebar-w) 1fr; }
.uix-shell[data-nav="rail"]   { grid-template-columns: var(--uix-sidebar-w-rail, 56px) 1fr; }
.uix-shell[data-nav="hidden"] { grid-template-columns: 0 1fr; }

.uix-shell[data-focus] { grid-template-columns: 0 1fr; grid-template-rows: 0 1fr; }
.uix-shell[data-focus] .uix-shell__topbar { display: none; }

.uix-shell__main--bleed { padding: 0; }            /* reclaim the 32px gutter */
Design sketch — token + React contract
/* tokens/base/size.json — make the rail width contractual (it's hardcoded 56 today) */
"sidebar-w-rail": { "$value": "56px" }

/* AppShell.tsx — widen the API, keep `collapsed` as a back-compat alias */
interface AppShellProps {
  nav?: 'full' | 'rail' | 'hidden';   // collapsed=true → nav='rail'
  focus?: boolean;                    // immersive; hides sidebar + topbar
  onExitFocus?: () => void;           // wire Esc + restore focus
}
Do
Keep three resting widths so the choice is reversible and legible. Persist per user. Restore focus and prior nav state on exiting Focus mode. Freeze the identifier column so horizontal scroll never orphans a row.
Don't
Don't make Focus mode the only answer — most days the rail is enough. Don't hide the nav with no visible way back. Don't ship edge-to-edge as the default; full-bleed is an opt-in for genuinely wide grids, not every table.
Why this belongs in UIx, not Tensor. The shell, the collapse, and the frozen column already live in the contract. Adding the hidden tier, focus mode, and full-bleed here means every product — Tensor, POSx, SHOPx — gets the wide-table answer for free, and it can’t drift. Solving it locally in Tensor is exactly the fork pattern this audit flags.
Putting it in motion

Suggested sequence

This slots into the existing Track U / ADX workstream rather than competing with it. Order is by unblock-value and cost.

  1. Ship the width ladder (part 3). Cheap, self-contained, high daily impact for analysts; no dependency on the token work. Deliver hidden tier + focus mode + full-bleed + persistence.
  2. Productize the cell vocabulary & selection system. Move the .uix-num / .uix-mono / .uix-cell-sub utilities and the selection column + bulk bar out of tables.html into table.css + a Table wrapper. Pairs with token U3 (--uix-row-selected-bg).
  3. Ship column management as real components. Wrap table-toolbar and view-menu in React; make resize and reorder work, not just render.
  4. Land the responsive ladder (priority columns → card transform) in table.css so it isn’t styleguide-only.
  5. Close the loop with the parity guard (U5). The consumer-parity check is what stops all of the above from being re-forked in Tensor.
The multiplier is governance, not features. Every prototype you promote is wasted if the downstream keeps forking. The single highest-leverage item across this whole audit is U5 — the consumer-parity guard — because it converts one-time shipping work into durable adoption.
