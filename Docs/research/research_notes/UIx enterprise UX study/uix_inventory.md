## 1. Keyboard and speed

### Takeaway
UIx already ships a full command palette (items mode with ranked, diacritic-folded search, recents, groups, shortcuts), a key-name model with platform glyphs and `aria-keyshortcuts`, shortcut hint bubbles on buttons, roving-focus lists, a keyboard row model in DataWorkspace, a keyboard "grab" for drag, an optimistic-value hook, and delayed-pending timing. What it does not ship is any shared shortcut registry, conflict detection, or "?" shortcut help sheet, and no prefetch/intent primitive beyond passing a router link through.

### Cited Findings
- `CommandPalette` / `CommandGroup` / `CommandItem` (412 lines). Items mode (HAR-1378): consumer passes `items`; palette filters, groups, moves the active option with ↑/↓ (Home/End on empty query) via `aria-activedescendant`, runs on Enter/click; `recent` list shown for an empty query; `onNavigate` for router hrefs; polite result count ("1 result / 3 results", HAR-1647) — [CommandPalette.tsx](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/src/components/CommandPalette.tsx)
- Palette ranking model: label-prefix > every token starts a word > every token contained > keyword match; case and diacritics folded ("ubersicht" finds "Übersicht"); items carry `keywords`, `description`, `shortcut` (`['Mod','K']`, set as `aria-keyshortcuts`), `disabled` — [command-palette-model.ts](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/src/command-palette-model.ts); exported `filterCommandItems`, `groupCommandItems` — [index.ts](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/src/index.ts)
- Palette CSS and tests: [command-palette.css](https://github.com/COx-ORG-H/UIx/blob/master/packages/tokens/styles/components/command-palette.css), [command-palette-items-dom.test.mjs](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/src/command-palette-items-dom.test.mjs), [tests/a11y/command-palette-items.spec.mjs](https://github.com/COx-ORG-H/UIx/blob/master/tests/a11y/command-palette-items.spec.mjs). Design spec says keyboard-opened overlays and the palette open with no animation (`[data-uix-instant]`) — [Docs/specs/2026-06-15-uix-v2-style-guide-design.md](https://github.com/COx-ORG-H/UIx/blob/master/Docs/specs/2026-06-15-uix-v2-style-guide-design.md)
- `Kbd`, `KbdCombo`, `ariaKeyShortcuts`, `KeyShortcut` type, `useKbdPlatform`: `Mod` = ⌘ on Apple, Ctrl elsewhere; server render uses `other` to avoid hydration flashes; spoken text "Control+K"/"Command+K" (HAR-1361, HAR-2031, HAR-2416) — [Kbd.tsx](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/src/components/Kbd.tsx)
- `ShortcutHint`: hover / `:focus-visible` bubble for `Button`/`ButtonLink` with `shortcut`, portalled top-layer popover, keys spoken once via `aria-describedby`, WCAG 1.4.13 hoverable/dismissable (HAR-2031, HAR-2416) — [ShortcutHint.tsx](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/src/components/ShortcutHint.tsx); tests [tests/a11y/shortcut.spec.mjs](https://github.com/COx-ORG-H/UIx/blob/master/tests/a11y/shortcut.spec.mjs), [tests/a11y/touch-shortcut-hints.spec.mjs](https://github.com/COx-ORG-H/UIx/blob/master/tests/a11y/touch-shortcut-hints.spec.mjs), [shortcut-dom.test.mjs](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/src/shortcut-dom.test.mjs)
- Individual hotkeys live inside components: `AppShell navHotkey` (e.g. `[`) toggles full/rail, ignores typing, modifiers, key repeat and open modals (HAR-1371) — [AppShell.tsx](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/src/components/AppShell.tsx); DataWorkspace search focus on Ctrl/⌘ + / — [DataWorkspace.tsx](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/src/components/DataWorkspace.tsx); `SearchBar` exposes an `id` "for a '/' shortcut that focuses it" (product wires the key) — [SearchBar.tsx](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/src/components/SearchBar.tsx)
- List keyboard navigation: `List roving` → `RovingList` (one tab stop, ↑/↓/Home/End, Enter/Space activate, survives item removal), shared `roving.ts` (`syncRovingStop`, `rovingStep`) also used by the calendar agenda — [ListRoving.tsx](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/src/components/ListRoving.tsx), [roving.ts](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/src/roving.ts), [List.tsx](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/src/components/List.tsx); menu typeahead test [tests/a11y/menu-typeahead.spec.mjs](https://github.com/COx-ORG-H/UIx/blob/master/tests/a11y/menu-typeahead.spec.mjs)
- DataWorkspace keyboard row model (HAR-2626): one row in tab order, ↑/↓/Home/End, Enter → `onRowActivate`, `activeRowId`/`onActiveRowChange` "to drive it from the product's own shortcuts (j / k)" — the j/k keys themselves are product-owned — [DataWorkspace.tsx](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/src/components/DataWorkspace.tsx)
- Focus return: `peekRowId` returns focus to the row a side Peek showed and plays the `.uix-arrival` cue (merged #295, experiment) — [DataWorkspace.tsx](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/src/components/DataWorkspace.tsx), [tests/a11y/peek-return.spec.mjs](https://github.com/COx-ORG-H/UIx/blob/master/tests/a11y/peek-return.spec.mjs). Focus-return code also present in CommandPalette, Dialogs, DiscardPrompt, InlineEdit, Menu, Popover, Lightbox, Toast, ToolbarMore, TableControls, Date/Time pickers, scheduling views (grep `returnFocus|restoreFocus|focus back` over `packages/react/src/components`). `FocusOnMount` focuses an outcome heading once — [FocusOnMount.tsx](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/src/components/FocusOnMount.tsx)
- `useKeyboardGrab` + `settleDrop`: Space/Enter picks up, arrows move one step, Space/Enter drops, Escape/blur cancels; each step announced politely; instant moves (HAR-2590, WCAG 2.1.1/2.5.7). SortableList, KanbanCard and DashboardCanvas have their own keyboard paths — [useKeyboardGrab.ts](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/src/hooks/useKeyboardGrab.ts)
- `useOptimisticValue(serverValue, commit, { onRollback })`: shows the change at once, rolls back on failure with a `rollbacks` counter to flash via `ChangeHighlight`; doc restricts it to reversible personal actions (star, pin, reaction, mark read, view order), never state transitions/approvals (HAR-2583) — [useOptimisticValue.ts](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/src/hooks/useOptimisticValue.ts)
- `useDelayedPending`: nothing for 300 ms, then visible ≥ 500 ms — [useDelayedPending.ts](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/src/hooks/useDelayedPending.ts); `toast.undoable(…)` in the imperative toast store (HAR-1363) — [toast-store.ts](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/src/toast-store.ts)
- Prefetch: the only references are the `UixRenderLink` adapter, so a router link "keeps client navigation and prefetch" (Breadcrumbs, Card, LinkTile, link.tsx) — [link.tsx](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/src/link.tsx)
- Keyboard a11y suites: [tests/a11y/keyboard.spec.mjs](https://github.com/COx-ORG-H/UIx/blob/master/tests/a11y/keyboard.spec.mjs), [tests/a11y/phase-46-9-keyboard.spec.mjs](https://github.com/COx-ORG-H/UIx/blob/master/tests/a11y/phase-46-9-keyboard.spec.mjs), [tests/a11y/scheduling-keyboard.spec.mjs](https://github.com/COx-ORG-H/UIx/blob/master/tests/a11y/scheduling-keyboard.spec.mjs)

### Inferences
- The primitives for showing and speaking shortcuts exist; what is missing is the layer above them: a page-level shortcut registry (scope, conflict detection, "not while typing" in one place), a discoverable shortcut sheet, and sequence keys (g then i). Today each component re-implements its own "ignore while typing / in modal" guard (AppShell has one).
- Any j/k, "/" or "c to create" behaviour is product-built, which ADR-0038's "hand-rolled equivalents are banned" pressure argues should move into UIx.

### Gaps
- No shortcut registry, `useHotkey`-style hook, or "?" shortcut help dialog found (grep for `shortcut registry|useShortcut|registerShortcut|useHotkey|hotkey|cheat sheet|KeyboardShortcuts`; only `navHotkey` and TipTap's internal `addKeyboardShortcuts` matched).
- No prefetch-on-intent / hover-intent data hook found; whether CommandPalette items mode supports async/server results, loading states or nested pages was not verified in the code read.

## 2. Dense data and tables

### Takeaway
This is UIx's deepest area. `DataWorkspace` (1,756 lines) already covers multi-sort, filter chips over `FilterEditor`, search, saved views, View menu (columns, density, zebra, freeze), pinned actions column, selection with cap and bulk bar, grouping, virtualisation, keyboard row model, row motion, maximise, responsive priority/card ladder and full empty/error/refresh states. Notable holes: no user column resize in React (CSS grip only), no in-cell/spreadsheet editing in the table, and performance gating is coarse.

### Inferences
- A study recommending "saved views, bulk actions, density, virtualisation, keyboard rows, multi-sort, grouping" would be recommending what already ships. Genuinely new table work would be: interactive column resize (with keyboard), in-grid cell editing / spreadsheet-style navigation across cells, column-level aggregation/summary rows, and copy/export of a selection.
- `virtualize` is off with grouping and pagination; large grouped lists are not windowed.

### Gaps
- No React column-resize behaviour found; no inline cell editing inside DataWorkspace found (InlineEdit exists generically, see area 4); no summary/totals row API seen in the props read (not exhaustively verified — only the props block of DataWorkspace was read).

## 3. AI-assist

### Takeaway
UIx has almost nothing AI-specific. The nearest pieces are a "check this" review state on inputs explicitly meant for assistant-filled values, confidence percentages in `MatchReview`, three-way `DiffViewer` and two-way `TextDiff` for reviewing proposed changes, an answer-first `InsightCard`, and markdown/rich-text rendering. No AI label/disclosure, streaming text, suggestion chips, prompt composer, citations, or feedback (thumbs) components were found.

### Cited Findings
- `Input` `review` state: "'Check this': a value the reader should confirm, not an error, e.g. one an assistant filled in (HAR-1814). Draws the warning border; `invalid` wins" — [Input.tsx](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/src/components/Input.tsx), [input.css](https://github.com/COx-ORG-H/UIx/blob/master/packages/tokens/styles/components/input.css)
- `MatchReview`: candidates with optional `confidence` rendered as a rounded percentage or "not scored"; bulk results (`MatchBulkResult`) — [MatchReview.tsx](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/src/components/MatchReview.tsx)
- `DiffViewer`: three-way (base/current/incoming) diff grouped conflicted/changed/added/removed, per-entry keyboard-operable accept/keep/mark-pending, `labelFor` human names, `renderValue`, `provenance` ("Edited by Ana, 12 Oct"), `controlSize` (HAR-1369) — [DiffViewer.tsx](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/src/components/DiffViewer.tsx), [tests/visual/diff-viewer.spec.mjs](https://github.com/COx-ORG-H/UIx/blob/master/tests/visual/diff-viewer.spec.mjs)
- `TextDiff`: two-way line/word diff, side by side or unified, `<del>/<ins>` with spoken "Removed/Added" (HAR-1368) — [TextDiff.tsx](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/src/components/TextDiff.tsx)
- `InsightCard`: headline is the answer, status text+icon, KPIs with comparison and target bullet, "honest coverage note", source and one action (HAR-1556) — [InsightCard.tsx](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/src/components/InsightCard.tsx)
- Text surfaces usable for assistant output: `Markdown` (`./markdown` entry), `RichTextEditor` (`./rich-text`, mentions, emoji), `Composer`/`ComposerBar`, `Comments`, `SearchSuggest` (free-text, ADR-0004) — [package.json exports](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/package.json), [Composer.tsx](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/src/components/Composer.tsx), [Docs/adr/0004-search-suggest-free-text.md](https://github.com/COx-ORG-H/UIx/blob/master/Docs/adr/0004-search-suggest-free-text.md)
- The only "AI" mention in planning docs defers "AI safety" for the docs site — [Docs/plans/2026-09-07-uix-documentation-site.md](https://github.com/COx-ORG-H/UIx/blob/master/Docs/plans/2026-09-07-uix-documentation-site.md)

### Inferences
- Because ADR-0038 bans hand-rolled UI in product staff apps (see Consumers below), any AI-assist pattern a product wants (AI badge, streaming answer, suggestion chips, accept/reject of a draft, confidence, source citations, feedback) must be built in UIx first. This is the clearest greenfield area of the seven.
- Existing review primitives (`Input review`, `DiffViewer` accept/keep, `MatchReview` confidence) are a natural base for an "AI proposes, human confirms" pattern rather than new standalone widgets.

### Gaps
- No streaming text / incremental markdown handling found in `markdown.ts` / `markdown-model.ts` (grep for `stream|partial|incomplete|unterminated` returned nothing).
- No AI disclosure label, suggestion chips, confidence meter outside MatchReview, or citation component found.

## 4. Forms and errors

### Takeaway
Form field infrastructure is mature: `Field` with error/warning/success/help, many specialised inputs, locale-aware date/time pickers, APG comboboxes, async `EntityPicker`, `InlineEdit` with conflict-aware retry, `SaveStatus`, button result feedback, and a dirty-form guard for Drawer/Modal. Gaps: the validation (error) summary exists only as CSS with no React component, there is no route/page-level unsaved-changes guard, and no general "someone else changed this record" conflict banner.

### Cited Findings
- `Field`: `label`, `hint`, `error` (announced with `role="alert"`, text or node), `warning`, `success`, `required`, `help` (InfoTip) and auto id association incl. Combobox — [Field.tsx](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/src/components/Field.tsx); tests [field-system-dom.test.mjs](https://github.com/COx-ORG-H/UIx/blob/master/packages/react/src/field-system-dom.test.mjs), [tests/a11y/form-fields.spec.mjs](https://github.com/COx-ORG-H/UIx/blob/master/tests/a11y/form-fields.spec.mjs), [tests/a11y/field-grid.spec.mjs](https://github.com/COx-ORG-H/UIx/blob/master/tests/a11y/field-grid.spec.mjs); a `react-hook-form` integration fixture runs in `test:a11y` — [tests/tests/field-combobox-fixture.tsx](https://github.com/COx-ORG-H/UIx/blob/master/tests/tests/field-combobox-fixture.tsx), [package.json](https://github.com/COx-ORG-H/UIx/blob/master/package.json)
