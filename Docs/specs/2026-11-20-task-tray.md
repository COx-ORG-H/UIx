# Task tray: background work that keeps running while you work

Date: 2026-11-20 · Status: built in this change · Source: the phone-OS motion study, Tier 1 item 5
(`Docs/research/reports/Smartphone OS motion for UIx.md`) · Roadmap: `Docs/component-roadmap.md`
had no earlier plan for it.

## Why

iOS Live Activities, Samsung's Now Bar, Android Live Updates and Xiaomi's Super Island all landed on one
pattern for long-running work: a small pill that opens on demand, holds several activities at once and
stays until they are done. UIx's latency ladder already asks for this: past about 10 s, show real progress,
the current step, and a way to leave while the work goes on. Until now UIx had only one-shot toasts,
inline `SaveStatus` and `BusyRegion`. TENSOR needs it for exports, CSV imports, bulk ticket updates and CMDB
discovery runs.

## What it is

- **`tasks`**, an imperative store in the style of `toast()`. It is plain module state, so a mutation
  helper or a route loader can start a task and a page change does not lose it.
  `tasks.start(title, options)` returns a handle with `update`, `complete`, `fail`, `cancel`, `dismiss`
  and an `AbortSignal`. `tasks.run(title, work, options)` wraps an async function. It completes on resolve,
  fails on reject, and treats an abort as a cancel.
- **`<TaskTray />`**, mounted once in the app shell next to `<Toaster />`. When no task exists it renders
  only its live region. Otherwise it shows a pill. The pill opens a panel that lists every task.

## Anatomy

```
              ┌──────────────────────────────────────┐
  panel       │ Background tasks       Clear finished │
  (region)    │ ◌ Export 4,000 tickets       Cancel  │
              │   Writing CSV · 62 %                  │
              │   ▓▓▓▓▓▓▓▓▓▓▓░░░░░░                   │
              │ ✓ Import users.csv   Open      ×     │
              │   1,204 users imported               │
              │ ● Bulk update        Retry     ×     │
              │   Failed: 12 tickets locked           │
              └──────────────────────────────────────┘
  pill              ( ◌  2 running · 1 failed  ⌃ )
```

- **Pill** (`button`, `aria-expanded`, `aria-controls`). It shows a progress ring for the running tasks
  (a spinner when any of them has no measurable end), then the counts as words: "2 running · 1 failed",
  "3 done". The number ticks with `Count`. Its accessible name starts with the tray's name ("Background
  tasks: 2 running, 1 failed"), so the visible words stay part of the name (WCAG 2.5.3).
- **Panel** (`hidden` while collapsed). It has a header with the tray name and "Clear finished" (shown
  only when a task has finished), then a `MotionList` of tasks, newest first. The list scrolls past
  `min(60vh, 28rem)`.
- **Task row** (`li`, `aria-busy` while running). It holds a mark (spinner or ring, a check, a red dot, a
  dash), the title (wraps, never truncated), a line with the step or result, and a `Progress` bar while
  running (determinate with `value`/`max`, otherwise the kit's indeterminate bar). The row's actions are
  Cancel while running and cancellable, and the result action (a button, or a link with `href`/`download`)
  plus Dismiss once finished. The state is written in words ("Done", "Failed", "Cancelled") for screen
  readers. Colour is never the only signal.

## States

| Task state | Mark | Line | Actions | Pill counts it as |
|---|---|---|---|---|
| running, determinate | ring at `value/max` | step · "62 %" (or `valueText`) | Cancel (if cancellable) | running |
| running, indeterminate | spinner | step | Cancel (if cancellable) | running |
| done | check (draws once) | result message | result action, Dismiss | done |
| failed | red dot | "Failed: " + message | result action (e.g. Retry), Dismiss | failed |
| cancelled | dash | "Cancelled" + last step | Dismiss | done (as "cancelled" in the name) |

| Tray state | Renders |
|---|---|
| no tasks | the live region only (no landmark, no pill) |
| tasks, collapsed | landmark + pill |
| tasks, expanded | landmark + panel above the pill |
| last task dismissed | the panel closes, the pill leaves, focus returns to where it was before the tray |

## Behaviour

- **Order and identity.** Newest first. A `start` with an existing `id` replaces that task in place, so
  "Retry" can restart the same row. Rows never re-sort when a task finishes, so a row does not move from
  under the pointer.
- **Finished tasks stay** until dismissed, cleared with "Clear finished", or `dismissAfter` passes
  (`complete({ dismissAfter: 5000 })`, opt-in). A download link must not vanish while someone reaches for it.
- **Result action.** It runs (or follows its link) and then the task is dismissed (`keep: true` keeps it).
- **Cancel.** The tray's Cancel aborts `handle.signal`, calls `onCancel`, and sets the state to cancelled.
  A later `complete`/`fail` from the work is ignored. Only `running` can become a final state.
- **`dismiss` on a running task** removes it from the tray. It does not stop the work; call `cancel` for that.
- **SPA navigation.** The store outlives every component. A tray that is remounted (a new layout) shows
  the same tasks, collapsed.

## Accessibility

- **Landmark.** While a task exists, the tray is `<section aria-label="Background tasks">` (a region). The
  label can be translated through `regionLabel` or `UixLabelsProvider` (`taskTray`).
- **Announcements.** The tray owns one persistent, visually hidden `role="status"` polite region. It is
  mounted even with no task, because a region inserted together with its text is often not read (the same
  reasoning as the Toaster). It announces start ("Started: Export 4,000 tickets"), done ("Done: Export
  4,000 tickets. 4,000 rows written"), failure and cancel. It never announces progress percentages. Tasks
  that already existed when the tray mounted are not re-announced.
- **`aria-busy`.** It is set on each running row, not on the region: the region stays readable while work
  is under way.
- **Keyboard.** The pill is a native button (Enter/Space). Tab moves through the open panel's buttons and
  links in reading order. Escape anywhere in the tray collapses it and puts focus on the pill.
- **Focus management.** Opening the panel leaves focus on the pill (a disclosure, not a dialog), so
  Shift+Tab and Tab behave the same as before. When an action removes the focused control (Cancel turns
  into Dismiss, a row is dismissed), focus moves to the same row's next control, else the next row's,
  else the previous row's, else the pill. When the last task goes, focus returns to the element that held
  it before it entered the tray. Focus outside the tray is never pulled in.
- **Targets** are at least 24 × 24 px. Forced colours keep every mark and border (system colours).
  `prefers-contrast: more` strengthens the pill and panel borders.

## Motion (inside the contract)

| Moment | Motion | Tokens |
|---|---|---|
| pill appears (first task) | fades and rises 8 px | `--uix-dur-slow`, `--uix-ease-out` |
| pill leaves (last task gone) | fades and sinks | `--uix-dur-exit`, `--uix-ease-out` |
| panel opens | grows from the pill: scale .96 → 1, rise, fade (origin at the pill) | `--uix-dur`, `--uix-ease-out` |
| panel closes | the reverse, faster | `--uix-dur-exit` |
| chevron | turns half a turn | `--uix-dur` |
| task added / removed | `MotionList`: a new row rises and fades in, a removed one fades in place, then the rows below glide up | list-motion tokens |
| progress | the bar's transform transition (Progress) | `--uix-dur` |
| task done | the check draws itself once | `--uix-dur-draw` |
| count changes | `Count` ticks once | Count's tokens |

Everything runs on transitions over transform and opacity, so it can be interrupted, with no layout
properties and no keyframe that moves. No step is longer than 300 ms, and nothing bounces or overshoots.
Under reduced motion (the OS setting or `data-motion="reduce"`), `motion.css` drops travel, scale and
rotation and keeps the fades. The check is simply there, and spinners and indeterminate bars pulse
instead of moving. `check-motion` passes over `task-tray.css` with no `motion-allow`.

## Layout

The tray is fixed at `bottom-center` (default), `bottom-start` or `bottom-end`. Its width is
`min(26rem, 100vw - 2 × --uix-space-4)`, so at phone width it spans the screen with a 16 px gutter and
never scrolls sideways. It stacks above overlays and below toasts (`--uix-z-toast` − 1). A modal dialog
covers it and makes it inert, which is intended: the dialog has the focus. The default places it away
from the Toaster's `bottom-end` corner. At phone width the two can overlap while a toast is shown;
toasts stay on top.

## API

```ts
const task = tasks.start('Export 4,000 tickets', { step: 'Collecting', value: 0, max: 4000, onCancel });
task.update({ step: 'Writing CSV', value: 2480 });
task.complete({ message: '4,000 rows written', action: { label: 'Download', href: url, download: 'tickets.csv' } });
task.fail({ message: '12 tickets locked', action: { label: 'Retry', onClick: retry } });

await tasks.run('Discovery run: Sarajevo DC', async (task) => { … task.update({ step }) … }, {
  success: (n) => ({ message: `${n} CIs found`, action: { label: 'Open', onClick: openRun } }),
  error: (e) => ({ message: String(e) }),
});

<TaskTray />                         // default store; position, regionLabel, open/defaultOpen/onOpenChange
```

## Out of scope (follow-ups)

- An inline placement (the pill in a top bar, the panel as a popover) for shells that want it there.
- Moving the Toaster above the tray at phone width.
- Persisting tasks across a full page reload. That needs the product's server state; the store is memory only.
- TENSOR adoption (exports, CSV import, bulk update, CMDB discovery). It goes through its own Linear slice.
