Column resize (enterprise UX study, roadmap #11): `DataWorkspace` `onColumnWidthsChange` (and `columnWidths`) turns it on. Each header gets a grip: drag it; or focus it, a `separator` with `aria-valuenow` / min / max in px, and use ← / → (8 px; also with Alt), Shift + an arrow (the next stop of the column-width scale), Home / End (the column's floor and the cap); or click it, without dragging, for a width popover with a number field, − / +, Fit to content and Default width (the single-pointer way, WCAG 2.5.7); a double-click fits the widest content. The widths are committed once per resize, when it ends (pointer up, key up, a width set in the popover), never per pointer move. A column narrows to its `minWidth`, else 340 px for a `uix-col--flex` title and 92 px for the rest; `resizable: false` (on a column or `idColumn`) keeps it fixed. Resize uses the fixed layout; without a flex column the first resize holds every column at its drawn width, so only the resized one moves. The cards step has no grips. table-engine: `ViewState.widths`, serialised by `serializeView` / `parseView` as `widths=id:px,…`; `COLUMN_WIDTH_SCALE`, `COLUMN_WIDTH_MIN`, `COLUMN_WIDTH_MAX`, `COLUMN_WIDTH_STEP`, `stepColumnWidth`, `columnWidthForKey`, `fitColumnWidth`, `setColumnWidth`, `ColumnWidths`. `Th` `resizeHandle` puts a grip outside the sort button. New `DataWorkspaceLabels`: `resizeColumn`, `resizeHint`, `columnWidth`, `columnWidthUnit`, `narrower`, `wider`, `fitColumn`, `defaultColumnWidth`. tokens: `.uix-table__resize` is a 24 px target inside its header (was 8 px across the edge, under the next header) with logical sides, and `.uix-col-resize*` styles the popover.
