Motion, rebuilt natively from a study of animate-ui (operator decisions 2026-11-08). No animate-ui code and no animation library: springs are CSS `linear()` curves on UIx tokens, and the rest is CSS plus small React hooks.

- **Tokens:** `--uix-ease-glide` / `--uix-dur-glide` (a spring with no overshoot, 280 ms, reads as ~175 ms) for marks that move between items; `--uix-ease-pop` / `--uix-dur-pop` (a 3 % overshoot) for a control growing from its trigger; `--uix-ease-tooltip` / `--uix-dur-tooltip` (animate-ui's tooltip spring, stiffness 400 / damping 31: 2 % overshoot, reads as ~165 ms, settled at 410 ms); `--uix-ease-enter` / `--uix-ease-leave` and `--uix-dur-swap-in` (340 ms) / `--uix-dur-swap-out` (130 ms) for content swapping inside a surface that stays; `--uix-swap-shift` (40 px); `--uix-swap-blur` (6 px) and `--uix-arrive-blur` (4 px); `--uix-stagger-rows` (30 ms); `--uix-scrim-blur` (4 px). `--uix-ease-spring` stays for compatibility.
- **One gliding hover mark** in Sidebar, Menu and Select lists (`useHoverGlide`): a single row-sized `aria-hidden` `.uix-glide` layer moved to the pointer's row with `transform` alone (it never touches the list's layout). Pointer only; a key press hides it. **Markup:** the sidebar `<nav>`, the menu popover and the select listbox gain an `aria-hidden` `.uix-glide` span as their first child; the sidebar also gains a hidden `.uix-sidebar__mark`. Exact-markup snapshots of these components need updating.
- **Sidebar:** the current-page tint slides to a clicked row (as Tabs); a group's rows arrive staggered from the inline end, clearing from a 4 px blur; expanding from the rail, labels fade in. The width still changes at once. **A group's rows no longer carry a bullet** (operator, 2026-11-08, as in animate-ui): they start where the parent's label starts (`padding-inline-start` = the row's padding, its icon and the gap).
- **Select and Menu:** the list grows from `.9`; its rows arrive top to bottom, 30 ms apart, 8 px in from the inline end, clearing from a 4 px blur (`--uix-arrive-blur`, driven per frame in script; none when opened from the keyboard). The picked option's check draws itself; the trigger's new value rises in (never on first render).
- **Tooltip** (animate-ui's tooltip, rebuilt natively): grows from `.7` out of its trigger on `--uix-ease-tooltip` and shrinks back into it on close (it had no exit before). It lingers `--uix-delay-tooltip-skip` (300 ms) after the pointer leaves, so moving to a neighbour carries the same bubble across: it travels there, its background resizing, while the old label slides out (130 ms) and the new one slides in (340 ms), 40 px along the way it travels, both clipped to the background and clearing from a 6 px blur. It is placed in the frame it opens (it was painted for one frame at the viewport's corner before it moved: the "jump"). Escape and blur close it at once. **Markup:** the bubble's content is `.uix-tooltip__content > .uix-tooltip__label`; during a hand-over an `aria-hidden` `.uix-tooltip__content--leaving` copy of the old label sits in the bubble for about 400 ms. `getByRole('tooltip')` text is unchanged at rest. The bubble is `overflow: visible` (the UA's popover `overflow: auto` made it 10 px taller for a frame mid-glide, so it landed too high).
- **Drawer:** side drawers float `--uix-drawer-gap` (8 px) in from the screen edges with `--uix-radius-lg` corners; the bottom sheet stays edge to edge. The panel arrives on the glide spring and fades (so reduced motion still shows it arriving); the dim fades in over a constant `--uix-scrim-blur` (the radius never animates: an animated full-page blur starves software rendering such as VDI desktops; set the token to 0px to turn it off). Touch and pen can drag it toward its edge to close (past a third, or a fling); with `dirty` it settles back and asks first; the mouse keeps close, Escape and the backdrop.
- **Modal:** the page behind blurs under the fading dim (constant radius).
- **Checkbox:** the tick draws itself (stroke over `pathLength` 1); the radio dot pops on the calmer `--uix-ease-pop`.
- **Animated icons:** `animate` on any icon (`<DownloadIcon animate />`): hovering its control plays one short motion (arrow nudge, plus/close quarter turn, gear one tooth, refresh half turn, bell tip, send lift, download/upload arrow, bin lid, copy sheet, star pop); a check draws itself on appear. Adds `data-icon` and `data-animate` only when set. Hover only; never under reduced motion.
- **Step entrance:** `.uix-anim-step-forward` / `.uix-anim-step-back` for a panel keyed by its step (16 px from the way the person is going, mirrored in RTL).
- **Blurs run in script, never in CSS:** animate-ui clears arriving text from a short blur, and so does UIx now (list rows, the tooltip's labels), with `blurIn` writing the radius each frame while CSS keeps the fade and the slide. A CSS animation or transition of `filter` crashed Linux WebKit's renderer on the first or second list open (measured, in the page and in a popover); the same blur written per frame, as animate-ui's motion library does, ran 40 rounds without a crash, and so did animate-ui's own tooltip. `check-motion` now rejects `filter` and `backdrop-filter` in transitions and `@keyframes`. The value rise-in, the sidebar labels and the step entrance still fade and move without a blur. The blur behind modals and drawers is constant: its radius never animates.
- **Gates:** `check-motion` passes with every new loop/moving rule behind reduced motion; `motion-glide-dom.test.mjs` and `tests/a11y/motion-glide.spec.mjs` (both themes) prove the glide, the tooltip landing, the staggered rows, the floating drawer, the icons and that keyboard and reduced motion get none of it.
