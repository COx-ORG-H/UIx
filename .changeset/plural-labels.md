Plural-aware labels and language packs (enterprise UX study, first five #3). Every kit label that carries a count (`dataWorkspace.selected` / `groupCount`, `commandPalette.resultsMany`, `select.selectedCount` / `results`, `entityPicker.results`, `matchReview.*Many`, `orgChart.reportsMany`, `ruleBuilder.issuesMany`, `fileDrop.fileMany`, `fileUpload.added` / `tooMany`, `filterEditor.selected`, `tagInput.count`, `textDiff.showUnchanged`, `auditLog.loaded`, the scheduling counts, …) now also takes the CLDR plural forms `{ one, few, other }`, picked with `Intl.PluralRules` in the new `UixLabels.locale`, or a function of the count. Strings and the old `…One` / `…Many` pairs behave exactly as before; English output is unchanged. New: `countLabel`, `pluralCategory`, `useUixLocale`, `usePluralLabel`, `UixCountLabel`, `UixPluralForms`, `UixLabelPack`; `useTable`'s announcement is translatable (`labels`, provider `table`, `DEFAULT_USE_TABLE_LABELS`); the date fields fall back to the provider's `locale`. New entries `@tensor_1/react/locales/en`, `/de`, `/bs`, `/hr`, `/sr-Latn`, `/sr-Cyrl`: complete, typed packs (a missing key fails the build); de, bs, hr and sr are machine-drafted and need a native review; sr-Cyrl is generated from sr-Latn by `scripts/sr-cyrl.mjs`. Type note: count label keys widened from `string` to `UixCountLabel`, so code that reads one of them as a string now needs `countLabel`. Docs: Foundations → Writing and translation.
