DataWorkspace follow-ups from the MOTUS and TENSOR adoptions of 2.50 (HAR-2631, HAR-2632). Minor, not the planned 2.50.1 patch: it adds a `--uix-*` token (`--uix-row-h-standard`), and an additive token is minor by the contract's semver table. Every change is additive. A workspace, table or filter that uses none of the new props renders as in 2.50.0, with two deliberate exceptions, both listed below: an empty toolbar band is no longer drawn, and `Table density="standard"` now writes `data-density="standard"`.

- **The id column as a sort key (HAR-2631):** `idColumn.id` names the key it answers to in `sort` / `onSortChange` (default `'id'`), and `idColumn.sortable` makes its header a sortable header exactly like a data column's: the same cycle, multi-sort with Shift + click / Shift + Enter / Shift + Space, the ordinal (`sortOrder` + `sortOrderLabel`) and `aria-sort`. It works with `multiSort`, the frozen and fixed layouts and `mobile`. Without `sortable` the header is 2.50.0's.
- **"Is none of" enum filters (HAR-2631):** the enum `FilterValue` takes `operator?: 'is-any-of' | 'is-none-of'` (absent: is any of). `FilterField.enumOperators` offers the choice. With both, `FilterEditor` shows a condition control (the kit `Select`) above the options, and the condition stays as values change. Without it, the editor is 2.50.0's. `summarizeFilter` says "Status: not Open, Closed" (`FilterSummaryLabels.noneOf`). A new `UixLabelsProvider` group, `filterSummary`, words the DataWorkspace chips. A preset never matches an excluding value. `enumColumnFilter(field, value)` maps the value to the table engine's `isAnyOf` / `isNoneOf`.
- **`Table density="standard"` holds (HAR-2631):** a new token, `--uix-row-h-standard` (56px), and `.uix-table[data-density="standard"] td` pins it. `Table` now writes `data-density` for every density it is given, so a page-wide `--uix-row-h` re-point (the kit's `:root[data-density]`, a product's spacing preference) no longer makes an explicitly standard table comfortable. A table that names no density still follows `--uix-row-h`. Printed pages keep compact rows.
- **A row's name without an id column (HAR-2632):** `rowLabel(row)` names the row checkbox when there is no `idColumn.text`. Precedence: `idColumn.text`, then `rowLabel`, then the row id. A table keyed by UUIDs is therefore not read as "Select 3f2a9c…". Keep the function stable, as rows are memoised.
- **No empty toolbar (HAR-2632):** the `role="toolbar"` band renders only when one of its parts is set: search, filters, saved views, Save changes / Save as, View, maximize or `toolbarEnd`. A bare workspace starts with its table, with no empty landmark and no gap above it.
- **`.uix-table-wrap` is positioned (HAR-2632):** `position: relative`, so absolute content in a cell (a visually hidden label) stays inside the scrolling wrap instead of widening the page. Sticky headers, frozen cells, the busy bar and the menus and popovers (top layer) do not depend on an outer frame.
- **The workspace pager in the provider's words (HAR-2631):** the DataWorkspace footer hands `Pagination` the `UixLabelsProvider` `pagination` group (it was English under any provider), and a new `pagination.labels` wins over it. `Pagination` itself stays server-safe and reads no context: a product that renders it directly passes `labels` from its own `useUixLabels().pagination`.
- **Fix (HAR-2632):** DataWorkspace measures the actions column of a fixed layout only where `Range` has layout methods. In jsdom (a consumer's tests) it keeps the fallback width instead of throwing "range.getBoundingClientRect is not a function".
