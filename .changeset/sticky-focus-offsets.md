Sticky-layer focus offsets (WCAG 2.2 SC 2.4.11 Focus Not Obscured, technique C43, failure F110; the enterprise UX study, roadmap item 7). The Toaster and the TaskTray register as fixed layers: their heights are kept in `--uix-sticky-top` / `--uix-sticky-bottom` on `<html>` with a ResizeObserver, and the page, the viewport shell's main and a maximized DataWorkspace take them as `scroll-padding`, so a focused row and a `#fragment` stop clear of the stack and the tray. `TableWrap` measures its sticky header into `--uix-sticky-head`, which the wrap's `scroll-padding-top` reads (default still `--uix-table-head-h`). A keyboard focus that lands under a layer where the page cannot scroll any further (a table at the window's bottom) is moved clear in code by the nearest scroller. New: `useStickyLayer(ref, { edge })`, `registerStickyLayer(element, edge)` and `stickyInsets()` for a product's own fixed bars, and `useVirtualRows().scrollToIndex(index, { align })`, which stops a row inside the scroller's padding and clear of the layers; DataWorkspace's windowed rows use it, and while a layer shows the windowed body ends with room as tall as the layer's reach, so the last row can scroll clear too. `useStickyInsets()` (and `getStickyInsets` / `subscribeStickyInsets`) give the live offsets. No visual change beyond scrolling.
